# Changelog

All notable changes to Crimson are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and Crimson uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Entries are generated from merged pull request metadata at release time rather
than maintained by hand, so there is deliberately no running `[Unreleased]`
section — that avoids a permanent merge-conflict hotspot. Categories are
`Added`, `Changed`, `Fixed`, `Performance`, `Security`, `Deprecated`, `Removed`
and `Developer`.

For user-facing release communication, see the
[GitHub Releases](https://github.com/CrimsonMail/crimson/releases) page. This
file is the technical history.
