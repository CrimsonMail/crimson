# Getting help with Crimson

Crimson is in early development and is not yet a usable mail client, so most
questions right now are about building it or contributing to it. Either is
welcome.

| You want to | Go here |
|---|---|
| Ask a question | [Discussions → Q&A](https://github.com/orgs/CrimsonMail/discussions/categories/q-a) |
| Suggest an idea | [Discussions → Ideas](https://github.com/orgs/CrimsonMail/discussions/categories/ideas) |
| Talk through a design | [Discussions → Development](https://github.com/orgs/CrimsonMail/discussions/categories/development) |
| Report a bug | [Open an issue](https://github.com/CrimsonMail/crimson/issues/new/choose) and pick the form that fits |
| Report a security problem | **Privately**, through the [Security tab](https://github.com/CrimsonMail/crimson/security/advisories/new) — never in an issue or discussion |

## Before asking

- The [README](README.md) covers building and the project's current status.
- [CONTRIBUTING.md](CONTRIBUTING.md) covers branches, pull requests and the
  rules code is reviewed against.
- The [architecture decision records](docs/decisions/) explain choices that
  often prompt questions, such as why there are no third-party libraries and
  why local storage uses ESE rather than SQLite.

## Please never post

Passwords, OAuth tokens, message contents, or other people's email addresses —
anywhere public, including logs and screenshots. Crimson's logs redact
credentials, but read anything before pasting it.

## Response times

Crimson is maintained by one person. Questions are answered, but not on any
guaranteed schedule.
